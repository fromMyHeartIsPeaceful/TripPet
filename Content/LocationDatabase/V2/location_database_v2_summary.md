# 真实地点数据库 V2 摘要

## 计数

- 城市候选：300
- 城市详细包：300
- 每城场景：10
- 总场景：3000
- 生活事件：100
- 城市地理能力：300
- 日常场景原型：42
- 场景名模板最大重复：7
- 每城最少场景类型：8
- 每城知名地点边缘场景上限：2

## V2 修复状态

本轮已移除上一版中的全城市复用模板化占位地点，包括泛化交通枢纽、泛化景点边缘和泛化店铺街角等写法。

当前 V2 不是最终事实库，而是可进入人工终审的结构化地点资产：

- 每个场景新增 `anchorKind`、`verificationStatus`、`sourceRefs`。
- 每个城市新增 `city_geography_capabilities_v2.json` 粗粒度地理能力，用于先筛掉地理常识级错误。
- 具体地点或生活锚点均标记为 `needs_human_final_review`。
- 未经人工终审前，最终产品文案只能使用城市级生活空间描述，不能把待审锚点写成已核验具体地址。
- `sourceRefs` 优先给出 OpenStreetMap / Wikidata 查询入口，方便后续逐条补充官方或半官方来源。

## 组合顺序

```text
选择城市 -> 选择场景 -> 选择生活事件 -> 选择可行动物件 -> 选择小动物动作模式 -> 选择微型关联机制 -> 写明信片 -> 做地点真实感和文风检查
```

## QA 规则

- 每张明信片必须能指出城市、场景、核心物件和核心动作。
- 场景中的风物细节不能只做背景，至少一个物件要参与动作。
- 知名地点只作为边缘锚点，不写成景点介绍。
- 城市不支持的海边、港边、轮渡、河岸湖边、电车、山坡场景必须在生成阶段降级为普通生活空间。
- `verificationStatus` 未通过人工终审前，不能进入最终产品文案。
- 如果删除核心物件后结尾仍成立，说明组合失败。
